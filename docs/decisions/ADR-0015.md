# ADR-0015: Data-Driven Library Service Boundary

- Status: Accepted
- Date: 2026-07-16
- Decision owners: Project maintainers
- Related requirements: `REQ-040`, `REQ-048`, `REQ-054`, `REQ-056`, `REQ-059`, `REQ-060`, `REQ-061`, `REQ-062`
- Extends: `ADR-0002`, `ADR-0003`, `ADR-0004`

## Context

Browser, hosted, importer, and administrative workflows need the same governed definitions while the simulation core must remain portable and deterministic. [Source PDF, pp. 25-29, 31-32, 39-40]

## Decision

All governed library access shall cross a versioned Library Service contract. It owns schema validation, dimensions, immutable revisions, dependency closure, provenance, license and publication policy, authorization, audit events, search, and resolution. The engine consumes a self-contained, validated `ComponentDefinitionPlan` execution bundle and produces explicit unresolved-reference diagnostics. It does not query any database or object store.

Clients shall not receive unrestricted database CRUD. Every mutation is a domain operation with optimistic concurrency and idempotency semantics.

## Consequences

- Storage technology can change without changing solver contracts.
- Offline resolution can implement the same semantic service contract locally.
- Library validation failures occur before solver preparation.

## Rejected alternatives

- **Solver queries PostgreSQL directly:** couples numerical code to deployment state.
- **Expose database rows as public API:** bypasses invariants and publication policy.

## Compliance

Direct engine-to-storage dependencies or unrestricted client CRUD require rejection or a superseding ADR.
