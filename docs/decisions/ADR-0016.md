# ADR-0016: Mixed Storage Responsibilities

- Status: Accepted
- Date: 2026-07-16
- Decision owners: Project maintainers
- Related requirements: `REQ-006`, `REQ-029`, `REQ-030`, `REQ-031`, `REQ-054`, `REQ-055`, `REQ-058`
- Extends: `ADR-0003`, `ADR-0004`, `ADR-0009`

## Context

Transactional metadata, evolving validated definitions, large immutable artifacts, and offline working state have different consistency and size needs. [Source PDF, pp. 25-26, 31-32, 36, 39]

## Decision

The initial hosted baseline shall use PostgreSQL for identity, ownership, permission, revision, dependency, publication, audit, and searchable metadata. Validated evolving definitions may use PostgreSQL `JSONB` with schema-version and required indexes. S3-compatible storage holds large immutable `.eesim` archives, assets, datasets, waveforms, and result bundles. IndexedDB holds local projects, caches, pending operations, and offline sync metadata.

A separate document database shall not be introduced unless a later ADR supplies measured query, scale, availability, or operational requirements that PostgreSQL `JSONB` cannot satisfy. Storage access stays behind repositories and the Library Service.

## Consequences

- The baseline avoids unnecessary multi-database operations.
- Large blobs do not inflate transactional tables.
- Offline remains a first-class mode.

## Rejected alternatives

- **One store for every data shape:** creates avoidable performance or transaction compromises.
- **Add a document database pre-emptively:** adds consistency and operations costs without evidence.

## Compliance

Changing store responsibility or adding a document database requires a superseding ADR with evidence and migration/rollback plans.
