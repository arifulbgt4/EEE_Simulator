# ADR-0019: Declarative Models and Executable Kernel Boundary

- Status: Accepted
- Date: 2026-07-16
- Decision owners: Project maintainers
- Related requirements: `REQ-024`, `REQ-032`, `REQ-040`, `REQ-054`, `REQ-056`, `REQ-063`
- Extends: `ADR-0002`, `ADR-0003`, `ADR-0008`

## Context

Data-driven authoring must not become arbitrary code execution. Some advanced models still require approved native, WASM, HDL, SPICE, or external-engine kernels. [Source PDF, pp. 21-29, 35-36, 39-40]

## Decision

Database and archive model content shall be declarative: typed parameters, equations from an allowlisted expression subset, lookup data, topology, bindings, and references. It is schema-validated, dimensionally checked, dependency-closed, resource-bounded, and compiled to an execution plan.

Executable kernels shall be versioned, allowlisted capabilities with reviewed provenance, license, deterministic policy, platform support, resource limits, and validation evidence. Imported executable formats remain untrusted and use the process/sandbox boundary from ADR-0008. Arbitrary database-stored source, bytecode, shell commands, dynamic imports, network access, or host filesystem access are prohibited.

## Consequences

- Most library growth is safe and data-driven.
- Specialist kernels remain possible through explicit governance.
- The engine can fail closed on unknown capabilities.

## Rejected alternatives

- **Evaluate arbitrary formulas or scripts from storage:** creates an unacceptable execution boundary.
- **Forbid all executable adapters:** prevents required external-model interoperability.

## Compliance

Expanding executable capability requires a versioned allowlist entry, threat review, sandbox policy, license review, and validation evidence; arbitrary execution requires a superseding ADR and is presumed unacceptable.
