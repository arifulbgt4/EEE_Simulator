# ADR-0017: Minimal Google OIDC and Personal Project Persistence

- Status: Accepted
- Date: 2026-07-16
- Decision owners: Project maintainers
- Related requirements: `REQ-006`, `REQ-029`, `REQ-031`, `REQ-057`, `REQ-058`
- Extends: `ADR-0003`, `ADR-0004`

## Context

Users need optional personal cloud persistence before advanced team collaboration, while guest and offline use must remain available. [Source PDF, pp. 25-26, 31-32, 41-42]

## Decision

An early release shall plan Google OIDC behind a provider-neutral identity boundary and personal project persistence. The contract includes issuer/audience validation, state, nonce, PKCE where applicable, verified claims, secure session rotation, logout, account linking, and audit events. Guest/offline projects remain usable without authentication.

Guest-to-account migration is explicit, idempotent, and non-destructive. It preserves local copies until cloud acknowledgement, resolves revision conflicts visibly, and supports export and account unlinking. Organization membership, invitations, enterprise RBAC, and advanced collaboration remain in R10 and `EPIC-AUTH-001`/`EPIC-COL-001`.

## Consequences

- A personal user can opt into persistence without forcing sign-in.
- Later identity providers can use the same boundary.
- Authentication implementation remains outside this documentation-only change.

## Rejected alternatives

- **Mandatory sign-in:** breaks local-first and guest access.
- **Move all R10 identity work earlier:** expands scope beyond personal persistence.

## Compliance

Removing guest/offline mode or moving organization/enterprise scope before R10 requires a superseding ADR.
