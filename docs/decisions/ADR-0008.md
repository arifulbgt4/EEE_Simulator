# ADR-0008: External Engine Adapter and Process Isolation Boundary

- Status: Accepted
- Date: 2026-07-11
- Decision owners: Project maintainers
- Related requirements: `REQ-024`, `REQ-026`, `REQ-028`, `REQ-030`, `REQ-032`, `REQ-035`

## Context

Mature external tools already address SPICE, RTL compilation, computer architecture, machine emulation, and GPU analysis. The source brief recommends integrating specialized engines rather than rebuilding all of them, with larger work on server workers. [Source PDF, pp. 21-26, 35-36, 43-44]

Imported models and executable inputs can consume unbounded resources or execute hostile behavior, and external projects retain independent licenses.

## Decision

- External engines shall integrate through a versioned `EngineAdapter` contract rather than become solver-internal APIs.
- The lifecycle shall include capability discovery, validation, preparation, run, progress/result streaming, pause, checkpoint, resume, cancel, and disposal; adapters shall explicitly report unsupported operations.
- ngspice, Verilator, and gem5 are candidate adapters, not mandatory linked dependencies of the public core.
- Xyce, QEMU, and any GPL or mixed-license engine shall remain behind an executable or process boundary and require documented legal review before distribution.
- Server adapters shall run in isolated containers or equivalent processes with no outbound network by default, read-only runtime filesystems, bounded scratch space, least privilege, and CPU, memory, process, time, and output limits.
- Cancellation shall terminate descendants, close streams, and remove temporary data according to retention policy.
- Adapter results shall identify engine name and version, command or configuration identity, input checksum, model provenance, seed, isolation policy, and diagnostics.
- A process boundary is an architectural and security control; it does not itself determine license compatibility. Distribution remains blocked until review.

## Consequences

- Engines can be added or replaced without changing the canonical project and job contracts.
- Hosted operators must maintain patched images, checksums, toolchain provenance, quotas, and audit evidence.
- Browser-only deployments degrade by declared capability rather than silently emulating an unsupported engine.

## Rejected alternatives

- **Link every engine into the core:** creates security, portability, maintenance, and licensing coupling.
- **Run compilers or models in the API process:** fails the workload-isolation requirement.
- **Trust imported files based on extension:** does not address malicious syntax, archives, or resource exhaustion.

## Compliance

Embedding an external engine, enabling network access for untrusted jobs, or distributing a restricted dependency requires a superseding ADR and security and license reviews.
