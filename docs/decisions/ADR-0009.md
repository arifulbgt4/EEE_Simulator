# ADR-0009: CRDT-Based Real-Time Collaboration

- Status: Accepted
- Date: 2026-07-11
- Decision owners: Project maintainers
- Related requirements: `REQ-006`, `REQ-031`, `REQ-032`

## Context

The platform is expected to support version history, comments, documentation, team collaboration, public circuit sharing, and reusable component libraries, including offline-capable small projects. [Source PDF, pp. 31-32, 41-42]

Concurrent schematic editing must converge after temporary disconnection without silently losing accepted edits, while simulation must run against stable content.

## Decision

- Real-time project editing shall use a Conflict-free Replicated Data Type (CRDT) model.
- The collaborative document shall cover schematic topology, positions, properties, hierarchy, annotations, and project documentation through typed operations; binary assets and large results remain content-addressed references.
- Stable object IDs shall survive concurrent editing, moves, and property updates.
- Reconnection shall merge causally valid edits and expose semantic conflicts that cannot be resolved safely, including incompatible pin-map, component deletion, or hierarchy changes.
- A simulation job shall bind to an immutable project revision created from a known converged state; live edits shall not mutate an active run.
- Comments, approvals, releases, access grants, and stored results shall reference immutable revisions or stable object IDs as applicable.
- WebSocket is reserved for collaboration presence and operation exchange. Simulation progress and result streaming use the job protocol rather than the collaboration channel.
- Hosted roles shall include `Owner`, `Editor`, `Commenter`, and `Viewer`; service operator permissions remain separate and least-privileged.

## Consequences

- Offline and concurrent edits can converge without central lockstep editing.
- CRDT convergence does not replace domain validation; invalid electrical or package mappings remain visible diagnostics.
- Persistence needs snapshots, operation retention or compaction, revision hashes, and migration tests.
- Presence is ephemeral and must not become authoritative project data.

## Rejected alternatives

- **Last-write-wins documents:** can silently discard concurrent accepted edits.
- **Database row locking for all edits:** does not support useful offline work.
- **Simulating directly from mutable collaboration state:** makes results irreproducible.

## Compliance

Changing convergence semantics, stable identity, or immutable simulation revision binding requires a superseding ADR and migration plan.
