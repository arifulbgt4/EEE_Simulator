# ADR-0014: Model, Symbol, Package, Pin, Board, and System Orthogonality

- Status: Accepted
- Date: 2026-07-16
- Decision owners: Project maintainers
- Related requirements: `REQ-037`, `REQ-038`, `REQ-048`, `REQ-050`, `REQ-051`, `REQ-052`
- Extends: `ADR-0004`, `ADR-0007`

## Context

Electrical behavior, schematic communication, physical appearance, pin mapping, board composition, and system composition change at different rates and require different validation. [Source PDF, pp. 22-23, 26-32, 35-37]

## Decision

Models, devices, symbols, packages, pin profiles, device-package bindings, boards/modules, and systems shall be separate stable, revisioned definitions. A package contains mechanical body and terminal geometry only; it cannot contain a device, MCU, board, module, system, firmware image, or circuit topology. A board is not a package. Bindings shall validate complete pin equivalence and cannot silently change electrical connectivity when appearance changes.

## Consequences

- One device may bind several packages and one package may serve several devices.
- Package designers remain constrained mechanical-appearance tools, not PCB CAD.
- The 74HC00, ATmega328P, and Arduino Uno examples can be represented without category confusion.

## Rejected alternatives

- **Package as the complete IC:** couples mechanical and electrical revisions.
- **Board represented as a large package:** hides real dependencies and interfaces.

## Compliance

Any schema that nests a device, board, or system inside a package requires rejection or a superseding ADR.
