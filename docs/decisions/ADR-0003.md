# ADR-0003: Local-First Execution and Isolated Cloud Workers

- Status: Accepted
- Date: 2026-07-11
- Decision owners: Project maintainers
- Related requirements: `REQ-006`, `REQ-029`, `REQ-030`, `REQ-032`, `REQ-033`

## Context

Small analog circuits, educational digital circuits, selected transistor blocks, visualization, and offline editing fit the browser. Large SPICE jobs, RTL compilation, architecture simulation, GPU analysis, Monte Carlo batches, and long thermal work need server resources. [Source PDF, pp. 25-26, 36]

The source brief also calls for project history, team collaboration, public sharing, and reusable libraries backed by durable cloud storage. [Source PDF, pp. 31-32]

## Decision

- Editing and supported small simulations shall be local-first and usable offline after required client assets are available.
- Routing to cloud execution shall be capability- and policy-based, visible to the user, and never a silent change of engine or fidelity.
- Heavy jobs shall run in container-isolated worker processes with no outbound network by default and explicit CPU, memory, process, wall-time, scratch-space, and output limits.
- Hosted metadata and relational state shall use PostgreSQL.
- Project archives, imported assets, checkpoints, and large results shall use S3-compatible object storage.
- Redis Streams shall provide the initial durable job queue and consumer coordination layer.
- Browser and service interfaces shall use the same versioned simulation request and result contracts.
- A cloud job shall support validation, queueing, progress and result streaming, cancellation, terminal diagnostics, and checkpoint/resume only when the selected engine declares it. [Source PDF, pp. 25-28, 36, 39]

## Consequences

- Local work remains responsive during service outages.
- Server operation requires quota, retention, cleanup, observability, and replay policies.
- A job records immutable project revision, model versions, engine version, configuration, and stochastic seed.
- Cloud availability may expand capacity but cannot redefine correctness.

## Rejected alternatives

- **Browser-only execution:** cannot meet the later large-job goals. [Source PDF, pp. 25-26]
- **Cloud-only execution:** violates offline editing and immediate small-circuit interaction.
- **Running heavy tools inside the API process:** breaks isolation and operational safety.

## Compliance

Changing the local/cloud boundary or the canonical persistence and queue technologies requires a superseding ADR and a migration plan.
