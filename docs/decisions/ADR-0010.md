# ADR-0010: Apache-2.0 Open-Source Core and Third-Party Boundary

- Status: Accepted
- Date: 2026-07-11
- Decision owners: Project maintainers
- Related requirements: `REQ-022`, `REQ-023`, `REQ-024`, `REQ-032`, `REQ-035`, `REQ-037`, `REQ-038`

## Context

The product is intended to have an open, reusable core and may also operate as a hosted service. It will interoperate with external simulation engines, standards, manufacturer models, community assets, and datasets whose licenses differ from the core.

The source brief recommends integration with existing open-source and specialist engines instead of attempting to replace all of them. [Source PDF, pp. 21-26, 35-36, 43-44]

## Decision

- The project's public core shall use the Apache License, Version 2.0.
- An optional hosted service may add operational capabilities without changing the license of core files or imported third-party artifacts.
- Every dependency, engine, model, dataset, symbol source, package asset, and generated artifact shall record provenance, version, license, modifications, and distribution status.
- Original IEC/ANSI-aligned schematic symbols and physical representations shall be created for the core; protected standards artwork and proprietary manufacturer assets shall not be copied without permission.
- GPL or mixed-license engines shall remain across the external process boundary in ADR-0008 and shall not be bundled with the core until a documented license review approves the exact distribution.
- Imported models retain their source terms. Import capability does not grant redistribution rights.
- A repository `NOTICE.md` and dependency/license matrix shall record required attributions and unresolved restrictions.
- A process boundary, hosted-service deployment, or dynamically downloaded artifact shall not be used as a claim of legal compatibility; maintainers must record review evidence for the actual use and distribution mode.

## Consequences

- Core contributors have a permissive default license and explicit contribution expectations.
- Distributions may omit adapters or artifacts whose provenance or license is unresolved.
- Model and asset ingestion needs quarantine states for missing or incompatible terms.
- Legal review remains a release gate, not an implementation afterthought.

## Rejected alternatives

- **No declared core license:** prevents reliable contribution and reuse.
- **Assume all external open-source tools can be bundled:** ignores license-specific obligations.
- **Relicense imported models automatically:** exceeds the project's authority.

## Compliance

Changing the core license or distributing a previously isolated restricted dependency requires a superseding ADR and documented legal review.
